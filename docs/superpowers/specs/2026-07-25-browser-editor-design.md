# AMacQ 离线浏览器配置编辑器设计

**日期：** 2026-07-25  
**状态：** 待用户审阅

## 目标

在保留现有 PowerShell + WPF 编辑器与 `.vbs` 启动器不变的前提下，增加一个可直接双击打开的离线浏览器版本。浏览器版完整保留现有编辑规则，并优先在 Chrome / Edge 中将用户授权选择的文件直接写回；不支持或未授权时，下载保持源文件名的修改版本。

## 范围

浏览器版包含以下现有功能：

- 分别选择按键与灵敏度两个 Lua 配置文件，并拒绝将同一文件用于两个角色。
- 读取并保留 UTF-8、UTF-8 BOM、UTF-16 LE、UTF-16 BE 编码信息。
- 从按键配置解析枪械、全局 `press` 和 `modeswitch` 设置。
- 显示鼠标型号及其可选按键。
- 编辑当前枪械的按键与灵敏度字段；不存在的字段保持禁用。
- 校验下拉选项与最多两位小数的数值输入。
- 写入按键时，按照现有规则清零其他枪械中相同字段的冲突按键。
- 优先保存回源文件；不可直写时下载原文件名不变的修改版。
- 刷新已选择的两个文件。

不包含网络访问、目录扫描、游戏进程交互、用户账号、服务端、数据库或文件上传。

## 文件结构

```text
AMacQ配置编辑器/
├─ AMacQGuiEditor.ps1            # 保持不变：现有 WPF 编辑器
├─ 启动AMacQ配置界面.vbs          # 保持不变：现有 WPF 启动器
├─ web/
│  ├─ index.html                 # 浏览器入口，可直接双击
│  ├─ styles.css                 # 深色主题、动画与响应式样式
│  └─ app.js                     # 配置模型、Lua 处理、界面和保存逻辑
└─ tests/
   └─ ...                        # 保留现有 WPF 测试；新增网页逻辑测试
```

## 架构与职责

### `web/index.html`

提供静态页面结构：侧栏/顶部控制区、文件选择与刷新控件、鼠标型号与枪械列表、全局设置、当前枪械字段、状态提示和应用按钮。页面不引入第三方依赖，不引用网络资源。

### `web/styles.css`

复刻当前 WPF 的紫蓝深色渐变、强调色、扫描线和交互反馈。宽屏采用左侧栏和右侧详情布局；窄屏将侧栏内容移至顶部，字段改为单列。动画仅使用轻量 CSS，并遵循 `prefers-reduced-motion`。

### `web/app.js`

按职责划分为逻辑清晰的模块/函数：

- 常量与字段定义：目标文件角色、数值规则、鼠标型号、触发方式、切换键、字段后缀及标签。
- 文件读写编解码：检测 BOM、解码为文本、按源编码重新编码。
- Lua 操作：读取数值/字符串赋值、发现枪械、替换指定值。
- 编辑模型：保存两个文件的文本、编码、名称和可选文件句柄；保存当前选择状态。
- 页面渲染：从模型构建枪械列表与字段，按当前鼠标型号更新按键选项。
- 操作控制：选择、刷新、应用、直接写回、下载回退与状态反馈。

核心编辑逻辑独立于 DOM，以便可用自动化测试验证。

## 页面与数据流

1. 用户双击 `web/index.html`，浏览器本地打开页面。
2. 用户点击“选择文件”，按键文件与灵敏度文件分别选择；支持 File System Access API 时请求文件句柄，否则使用普通文件选择控件。
3. 页面读取文件内容、检测编码并在内存创建配置模型；解析全局设置和枪械列表。
4. 用户选择鼠标型号和枪械，页面根据模型填入可编辑字段，并禁用不存在的 Lua 变量。
5. 点击“应用”后，先校验输入，再更新内存内两份 Lua 文本并清理冲突按键。
6. 若两个文件均持有可写句柄且权限有效，按原编码写回两个源文件；若不可用、权限拒绝或写回失败，则下载两份修改文件，文件名保持源文件名不变。
7. 页面显示“应用成功”或“已下载修改文件，请替换原文件”等明确状态；发生失败时保留当前编辑状态。

## 保存策略与安全边界

- 仅处理用户显式选择的两个文件。
- 页面不扫描磁盘、不读取固定路径、不上传任何内容，也不与游戏进程交互。
- Chrome / Edge 中优先使用 `showOpenFilePicker` 获取用户授权的文件句柄，并使用 `createWritable()` 写回。
- 在 `file://` 环境或不支持 File System Access API 的浏览器中，保存模式为下载回退。
- 下载内容使用原始文件名；两文件由浏览器分别下载，用户手动覆盖原文件。
- 页面持续显示当前保存能力：可直接写回或下载后替换。

## 错误处理

- 同一文件被选为两个配置角色：拒绝加载。
- 文件解码失败、配置文件不存在有效枪械、全局变量缺失或目标变量无法替换：显示文件角色和具体原因。
- 未选择必要下拉项、数值格式错误：阻止应用并提示字段名称。
- 文件权限被拒绝、写入失败、文件被占用：保留内存编辑结果，并自动尝试下载回退；下载同样失败则显示错误。
- 刷新时重新读取当前两个文件；刷新失败时清除无效加载状态并显示原因。

## 兼容性

- 主要支持最新版 Microsoft Edge 与 Google Chrome。
- Firefox、Safari 和不支持 File System Access API 的浏览器：可选取、编辑和下载，不支持直接覆盖源文件。
- 窄屏及窗口缩小时使用响应式布局，确保所有编辑字段可操作。

## 测试与验证

新增无依赖的网页逻辑测试，覆盖：

- 数值和字符串 Lua 赋值的读取与替换。
- 枪械识别与不存在字段禁用。
- 数值格式校验。
- 按键冲突时其他枪械字段清零。
- UTF-8、UTF-8 BOM、UTF-16 LE、UTF-16 BE 的解码和重新编码。
- 两个配置文件不同的校验。
- 直接写回不可用时的下载回退决策。

同时运行现有 Pester 测试，确认新增网页文件不会影响 WPF 编辑器与启动器。手工在 Edge / Chrome 测试文件选择、刷新、切换枪械、保存直写和下载回退。
